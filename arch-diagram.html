🛡 Trust Boundary 1 — LLM is sandboxed from the database

The LLM never opens SQLite or runs SQL. It only receives safe tool schemas and tool results from the MCP server. The MCP server is the only process that imports the SQLite layer (see server.py top comment and mcp_client.py docstring).

🛡 Trust Boundary 2 — Write safety: delete requires explicit confirmation

Deletion is a two-step request/confirm/cancel workflow held in a sidecar file (.pending_deletions.json), not SQLite. Each request is session-scoped, expires in 5 minutes, is validated (record fingerprint, foreign-key dependencies, cascade confirmation), and the operational database is never changed until step 2 succeeds. Direct delete_student is disabled (server.py:83).

Secondary Details (cards, not edges)

  • Analytics (analytics.py): pure helper functions (branch counts, average marks, distributions) for chart data — no I/O.
  • Charting (charting.py): validates the MCP chart payload (type, row limit ≤ 500, scatter requires X+Y) and renders Plotly figures; supports pie, donut, bar, horizontal_bar, line, histogram, scatter.
  • Data Provenance (database.py): every table carries provenance_id + data_origin ('verified_public' / 'synthetic_demo' / 'unknown'); demo rows are labeled synthetic_demo.
  • MCP Inspector: mcp dev src/mcp_database_assistant/server.py — inspect tool schemas and call them directly.
  • Tests (tests/): schema creation, legacy migration preservation, FK-backed college tables, CRUD, relational queries, charting.
